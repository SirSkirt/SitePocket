PROJECT ARCHITECTURE
--------------------
- SitePocket frontend: src/main.ts, src/style.css (TypeScript, Tauri 2,
  styled dark-blue/teal interface). UI handles library, import, Game Options,
  icons, touch layouts, and debugger popups.
- Tauri Rust manager backend: src-tauri/src/lib.rs
- Shared Rust authoritative data/registry/importer:
  crates/webcask-core/src/lib.rs
  The InstalledApp registry contains per-app ID/name/kind, URL or local port,
  entry point, Game View, window mode/size, and Android touch mappings.
- Windows standalone runner:
  crates/webcask-runtime/src/main.rs (Wry/WebView2);
  src-tauri/resources/webcask-runtime.exe is packaged into installer.
  Windows game/app shortcuts launch WebCask independently of manager.
- Android player: src-tauri/src/android_player.rs
  Opens second Tauri WebViewWindow in a registered WebCaskActivity.
- Android local game server: src-tauri/src/mobile_server.rs.
  Serves extracted HTML5 content using a read-only loopback HTTP origin
  (127.0.0.1:<game-port>), with correct WASM MIME and path traversal checks.
  No need for internet for genuinely self-contained ZIP games.
- ZIP importer: crates/webcask-core/src/lib.rs; Android document staging via
  crates/tauri-plugin-android-zip-import and Kotlin ContentResolver.
- Icon handling: src-tauri/src/icons.rs; installed apps can use automatic
  favicons/bundled icons or user-supplied custom images. Windows shortcuts
  receive the selected ICO. Android icon matches the Windows SitePocket logo.
- Android native files: src-tauri/android/WebCaskActivity.kt,
  WebCaskNativeLog.kt, WebCaskSplitInitializer.kt,
  webcask_split_config.xml. Kotlin bridge:
  crates/tauri-plugin-android-zip-import/android/src/main/java/
  dev/sitepocket/zipimport/ZipImportPlugin.kt.
- Debugger Rust store: src-tauri/src/diagnostics.rs; JS game-side collection:
  src-tauri/src/android_debug.js; in-game touch controls:
  src-tauri/src/android_touch.js; manager debugger UI in src/main.ts.
- CI:
  .github/workflows/windows-release.yml
  .github/workflows/android-release.yml
  .github/scripts/setup-webcask-android.py

IMPLEMENTED USER-VISIBLE FEATURES
----------------------------------
WINDOWS:
- Install URL as individual website/app even without PWA manifest.
- Import local HTML5/JS/WASM games from folders or ZIP files.
- Detailed import failure messages next to Import Game button.
- Standalone WebCask runner, individual browser profiles, desktop shortcuts.
- Game View/Game Focus (expands canvas/iframe), windowed/maximized/fullscreen
  launch options, per-game window size and saved defaults.
- Experimental same-origin online-game capture into an offline candidate.
  This cannot guarantee all game files or support DRM/auth/CDNs.
- Discover/download website icons, detect local game icons, customize icons,
  propagate chosen icons to shortcuts and windows.

ANDROID PREVIEW:
- Android 12L+ (minSdk 32), arm64 preview, Android system WebView.
- Import HTML5 game ZIPs using Android Files and a native ContentResolver
  bridge, extract into per-app data. The user VERIFIED ZIP import now works.
  Android folder importing remains unsupported.
- Per-game on-screen controls: editable positions, labels, button sizes,
  keyboard key mappings, up to 24 buttons, hold/multi-touch and toggle.
  These emit SYNTHETIC DOM KeyboardEvents; some games ignore them, particularly
  games needing trusted events or cross-origin iframes.
- Local offline game server for imported ZIP content; does not currently
  support HTTP Range requests; externally hosted assets still require network.
- Android APKs use a stable DEVELOPMENT preview signing identity and
  incremental Android version codes. Old previews 1–6 used changing signers
  and required ONE uninstall when migrating. Preview 7 onward should update
  in place as long as same signing identity and higher version code are used.
  Preserve app ID dev.sitepocket.desktop to avoid breaking installs.
- Important security caveat: the preview keystore is currently committed to
  the repo for testing. It MUST be replaced by a privately held production key
  in GitHub encrypted secrets BEFORE any public/production/Play Store release.
  Do not publish keystore passwords or raw key contents in reports.

REPAIRS JUST MADE (BUILT SUCCESSFULLY AS PREVIEW.12; NOT YET PHONE-TESTED)
-------------------------------------------------------------------------
1. Android player uses .activity_name("WebCaskActivity") and registers a
   secondary Android Activity/AndroidX Window embedding support. The Tauri
   launch command was made async with spawn_blocking to avoid blocking the
   manager's synchronous IPC while the Activity initializes.
2. New "android-activity-build-requested" diagnostic stage before
   WebviewWindowBuilder::build().
3. Native Kotlin logger independent of injected game JavaScript:
   - Activity onCreate/onResume/onPause/onDestroy milestones.
   - Native WebView object creation, progress.
   - WebChromeClient console warnings/errors.
   - Renderer unresponsive/responsive callbacks.
   - Background native Activity UI-thread heartbeat; flags >12s stalls.
   - Events written to bounded app-private JSONL journal AND Android Logcat
     tag "WebCaskNative".
   - Rust bridge reads journal, deduplicates/merges with JS/Rust debugger
     timeline; manager popup supports Copy Report and retains events across
     restarts. Does not automatically upload diagnostics.
4. Fixed GitHub Android workflow corruption. It previously duplicated/
   interleaved blocks and GitHub created no jobs. Current valid workflow is
   restored from Preview.9 and invokes:
     python3 .github/scripts/setup-webcask-android.py
   AFTER 'npx tauri android init --ci' to copy native Kotlin Activity/logger,
   register manifest entries and AndroidX dependencies. PREVIEW.12 PASSED CI.

EXPECTED DEBUGGER TIMELINE AFTER NEXT TEST:
  runtime launch-started
  android-activity-build-requested
  native-activity-create-requested
  native-activity-created

IMPORTANT CONTEXT AND GUARDRAILS
--------------------------------

  should depend on an upstream game such as Tweetcraft. BlockBend is an
  independent user-developed voxel game used for testing.
- User prefers separate, replaceable modules and functionality based on
  generic web games, rather than reproducing one game's internals.
- Preserve each app's own files, browser profile and settings across updates.
- ZIP extraction, pathname validation and HTTP loopback origin security are
  important. Do not allow arbitrary website native API access or unrestricted
  file access. Never assume file:// is adequate for WASM/fetch/workers.
- SitePocket UI styling: dark navy/teal, compact, in-app messages. Debugger
  only opens when an error occurs, and should allow Copy/Clear/Close.
- The GitHub repository is currently PRIVATE. Use connected GitHub tools for
  edits. Do not accidentally flip visibility, change license, or upload secrets.
- README.md contains detailed implementation notes and caveats. Review it.
